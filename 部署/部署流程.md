# Farm 项目 — 部署流程

> ## 🎯 部署总览（按此顺序执行）
>
> ```
> ① 部署后端到腾讯云 CVM（Docker）⭐ 最先做！
> ② 本地前端连接远程后端验证 ⭐ 确认后端无问题
> ③ 购买域名 + ICP 备案（约 1-2 周）⭐ 可与①②并行启动
> ④ 构建前端 + 部署到 EdgeOne Pages
> ⑤ 绑定自定义域名 + DNS 解析
> ⑥ 全链路验证
> ```
>
> **为什么先部署后端？**
> - ✅ 后端是核心服务，先确保 API 正常运行
> - ✅ 本地前端开发模式可直接代理到远程后端验证，无需部署前端
> - ✅ 确认后端无问题后再部署前端，避免前后端同时排查问题
>
> **为什么域名和备案要尽早启动？**
> - ✅ EdgeOne Pages 中国大陆加速区域**必须绑定已备案域名**
> - ✅ 默认域名仅支持 3 小时预览，不能持续使用
> - ✅ 备案审核需 1-2 周，可以和步骤①②并行准备

## 一、架构概览

### 1.1 生产环境架构

```
用户浏览器
    │
    ├── 页面请求 → EdgeOne Pages（全球 CDN）  ← 免费托管前端
    │              https://你的域名
    │              ├─ Vue SPA 页面
    │              └─ 静态资源 (JS/CSS/图片)
    │
    └── API 请求 → 腾讯云 CVM 服务器           ← 直连后端
                    http://服务器地址:39080/api/*
                    ┌───────────────────────┐
                    │ Docker: farm-backend   │  ← Spring Boot 容器
                    │ (Java 11 + MyBatis)    │
                    └───────────┬───────────┘
                                │  :3306
                    ┌───────────▼───────────┐
                    │ Docker: farm-mysql     │  ← MySQL 8.0 容器
                    └───────────────────────┘
```

| 组件 | 部署位置 | 端口 | 费用 | 管理方式 |
| ---- | -------- | ---- | ---- | -------- |
| Frontend | **EdgeOne Pages** | HTTPS | **免费** | EdgeOne 控制台/CLI/MCP |
| Backend | 腾讯云 CVM | **39080** | 按服务器计费 | `docker compose` |
| MySQL | 腾讯云 CVM | 13306 | 同上 | `docker compose` |
| 域名 | 腾讯云 DNSPod | - | ¥9-83/年 | DNSPod 控制台 |

### 1.2 验证阶段架构（步骤②使用）

```
本地浏览器 (localhost:8081)
    │
    ├── 页面请求 → Vue Dev Server (本地 npm run serve)
    │
    └── API 请求 → vue.config.js 代理 → 腾讯云 CVM:39080
                                        ┌───────────────────┐
                                        │ Docker: farm-backend│
                                        │ Docker: farm-mysql  │
                                        └───────────────────┘
```

### 1.3 前后端通信方式

**不使用 Edge Functions，前端直接请求后端：**

```
浏览器加载页面：https://你的域名/                → EdgeOne CDN 返回 Vue SPA
浏览器发送 API：http://服务器地址:39080/api/*  → 直连 CVM 后端
```

关键配置：
1. **前端** `MyAxios.js` 的 `baseURL` 在生产环境设为 `http://服务器地址:39080/api`（通过 `.env.production` 配置）
2. **后端** 已配置 CORS 跨域，允许来自任意 Origin 的请求（动态反射 Origin）

### 1.4 为什么不用 Edge Functions？

| 对比项 | 直连后端（本方案） | Edge Functions 代理 |
| ------ | ------------------ | ------------------- |
| 复杂度 | **简单**，无需额外代码 | 需要编写和维护 Edge Functions |
| CORS | 需要后端配置（✅ 已配好） | 无（同源） |
| 服务器 IP | 暴露在请求中 | 隐藏（通过 EdgeOne 中转） |
| 请求路径 | 浏览器 → CVM 直连 | 浏览器 → EdgeOne → CVM |
| 适合场景 | **个人/内部项目** | 对安全性要求高的项目 |

## 二、部署后端到腾讯云 CVM ⭐ 第一步，最先做！

> **前置条件**：已有腾讯云 CVM 服务器（服务器地址），已安装 Docker
>
> 完成这一步后，后端 API 就可以对外提供服务了 🚀

### 2.1 安全组放行端口

登录 [腾讯云安全组控制台](https://console.cloud.tencent.com/cvm/securitygroup)：

| 方向 | 协议 | 端口 | 来源 | 用途 |
| ---- | ---- | ---- | ---- | ---- |
| 入站 | TCP | **39080** | 0.0.0.0/0 | **后端 API（必须开放）** |
| 入站 | TCP | 8888 | 你的IP | 宝塔面板 |
| 入站 | TCP | 13306 | 你的IP | MySQL 远程连接（可选） |
| 入站 | TCP | 22 | 你的IP | SSH |

> ⚠️ **重要**：39080 端口必须对公网开放，因为前端需要直连后端 API。
>
> 💡 **提示**：当前安全组已放行 `39000-40000` 端口范围，39080 已包含在内。

### 2.2 服务器环境确认

通过宝塔面板或 SSH 确认 Docker 已安装：

```bash
docker --version
docker compose version
```

> **注意**：**不需要**宝塔创建网站！前端在 EdgeOne Pages 上，不在服务器上。

### 2.3 上传项目文件到服务器

需要上传的文件：

```
/opt/farm/                          ← 服务器目标目录
├── backend/                        ← Spring Boot 后端源码
│   ├── src/
│   ├── pom.xml
│   └── Dockerfile                  ← 多阶段构建配置
└── docker-compose.yml              ← MySQL + Backend 服务定义
```

> ⚠️ **注意**：`docker-compose.yml` 放在 `/opt/farm/` 根目录（不是 `部署/` 子目录），因为其中 `build.context: ./backend` 是相对于 docker-compose.yml 所在目录的路径。

#### 方式 A：宝塔面板上传（推荐）

1. 登录宝塔面板：`http://服务器地址:8888`
2. 进入 **文件** 管理
3. 创建目录 `/opt/farm/`（如果不存在）
4. 上传整个 `backend/` 文件夹到 `/opt/farm/backend/`
5. 上传 `部署/docker-compose.yml` 到 `/opt/farm/docker-compose.yml`

**操作细节**：

- 宝塔文件管理器支持拖拽上传和压缩包上传
- 如果 `backend/` 文件较多，建议先在本地压缩为 `backend.zip`，上传后在宝塔中解压
- 确认上传后的目录结构：`/opt/farm/backend/Dockerfile` 和 `/opt/farm/backend/pom.xml` 必须存在

#### 方式 B：SCP 命令上传

```bash
# 在本地 PowerShell 执行
scp -r e:\Workspace\AI\Farm_optimize\backend root@服务器地址:/opt/farm/
scp e:\Workspace\AI\Farm_optimize\部署\docker-compose.yml root@服务器地址:/opt/farm/
```

#### 方式 C：Git 拉取（如果代码已推送到远程仓库）

```bash
ssh root@服务器地址
mkdir -p /opt/farm
cd /opt/farm
git clone <你的仓库地址> .
# 然后把 docker-compose.yml 复制到 /opt/farm/ 根目录
cp 部署/docker-compose.yml ./
```

### 2.4 启动 Docker 服务

通过宝塔面板的 **终端** 或 SSH 登录服务器后执行：

```bash
cd /opt/farm

# 构建并启动（首次会下载 Maven 镜像 + 编译 Java，约 3-5 分钟）
docker compose up -d --build

# 查看容器状态
docker compose ps
```

预期输出：

```
NAME           STATUS                    PORTS
farm-backend   Up                        0.0.0.0:39080->8080/tcp
farm-mysql     Up (healthy)              0.0.0.0:13306->3306/tcp
```

> ⚠️ **如果构建失败**：检查服务器内存是否 ≥ 2GB，内存不足可能导致 Java 编译 OOM。解决方案见「常见问题」章节。

### 2.5 验证后端服务

```bash
# 2.5.1 服务器本机测试
curl http://127.0.0.1:39080/api/login

# 2.5.2 从外部测试（确保安全组已放行 39080）
curl http://服务器地址:39080/api/login

# 2.5.3 测试 CORS（模拟浏览器跨域请求）
curl -H "Origin: https://example.com" \
     -H "Access-Control-Request-Method: POST" \
     -X OPTIONS \
     http://服务器地址:39080/api/login -v

# 2.5.4 查看后端日志（排查问题用）
docker logs farm-backend --tail 30

# 2.5.5 查看 MySQL 日志
docker logs farm-mysql --tail 30
```

> ✅ **成功标志**：curl 返回正常的 JSON 响应，且 CORS 测试中响应头包含 `Access-Control-Allow-Origin`

## 三、本地前端连接远程后端验证 ⭐ 确认后端无问题

> **前置条件**：步骤二已完成，后端 API 可正常访问
>
> 这一步**不需要部署前端到任何服务器**，只在本地运行开发服务器验证

### 3.1 配置前端代理

`frontend/vue.config.js` 已配置代理到远程后端：

```js
// vue.config.js
module.exports = {
  publicPath: "/",
  devServer: {
    port: 8081,
    host: "localhost",
    proxy: {
      "/api": {
        target: "http://服务器地址:39080/",
        changeOrigin: true
      }
    }
  },
  productionSourceMap: false
};
```

> ✅ 此配置已就绪，无需修改。

**工作原理**：

| 环境 | baseURL | 请求路径 |
| ---- | ------- | -------- |
| 开发 (`npm run serve`) | `/api` | → vue.config.js 代理 → `服务器地址:39080` |
| 生产 (`npm run build`) | `.env.production` 中的值 | → 浏览器直连 `http://服务器地址:39080/api` |

### 3.2 启动本地前端开发服务器

```bash
cd e:\Workspace\AI\Farm_optimize\frontend

# 安装依赖（如果还没安装）
npm install --registry=https://registry.npmmirror.com

# 启动开发服务器
npm run serve
```

启动成功后访问 `http://localhost:8081`。

### 3.3 验证清单

在浏览器中逐一测试：

- [ ] 访问 `http://localhost:8081` 显示登录页面 ✅
- [ ] 输入账号密码能成功登录 ✅
- [ ] 登录后页面功能正常（菜单、数据展示等）✅
- [ ] 浏览器 F12 控制台 Network 面板中，API 请求地址为 `http://localhost:8081/api/...`（由代理转发到远程后端）✅
- [ ] 浏览器控制台无 CORS 错误 ✅
- [ ] 不同角色登录后功能正常 ✅

> 🎉 **全部通过 = 后端部署成功！可以继续部署前端到 EdgeOne Pages。**
>
> ❌ **如果有问题**：查看「常见问题排查」章节，或检查后端日志 `docker logs farm-backend --tail 50`

## 四、购买域名 + ICP 备案 ⭐ 可与步骤二三并行

> **这一步是 EdgeOne Pages 中国大陆加速的前提条件。**
>
> EdgeOne Pages 的默认域名仅支持 3 小时预览，**必须绑定自定义域名才能持续使用**。
>
> 如果选中国大陆加速区域，域名**必须完成 ICP 备案**。

### 4.1 为什么需要域名和备案？

| 访问方式 | 能用吗 | 说明 |
| -------- | ---- | ---- |
| 默认域名（无自定义域名） | ❌ | 仅 3 小时预览，超时返回 401 |
| 自定义域名 + 未备案 | ⚠️ | 只能选「全球不含中国」区域，国内访问稍慢 |
| **自定义域名 + 已备案** | ✅ **推荐** | 可选中国大陆区域，国内 CDN 极速 |

来源：[腾讯云官方文档 - Pages 域名管理概览](https://cloud.tencent.com/document/product/1552/127403)

### 4.2 购买域名（腾讯云）

#### 推荐域名及价格（2025 年最新）

| -------- | --------- | --------- | ------- | ------ | ---- |
| **.cn** | **¥8.8** | ¥33 | ¥38 | ⭐⭐⭐⭐⭐ | 中国国家顶级域名，备案首选 |
| **.com** | **¥1** (企业) / ¥33 (个人) | ¥75 | ¥90 | ⭐⭐⭐⭐⭐ | 全球最通用，信誉度最高 |
| **.top** | ¥14 | ¥32 | ¥28 | ⭐⭐⭐⭐ | 便宜 |

| **.xyz** | **¥1** | ¥10 | ¥12 | ⭐⭐⭐ | 最便宜选项之一 |

> 💡 **推荐**：农场管理系统选 `.cn`（¥8.8/年）或 `.com`（新用户 ¥1-33/年），性价比最高且专业感强。
>
> 📍 **购买地址**：[腾讯云域名专场特惠](https://cloud.tencent.com/act/pro/domain)

#### 购买步骤

1. 打开 [腾讯云域名注册页面](https://dnspod.qcloud.com/domains/add)
2. 输入你想注册的域名（如 `farm-optimize`），选择后缀（如 `.cn`）
3. 点击查询，确认域名可用
4. 加入购物车 → 结算
5. **填写域名信息模板**（用于实名认证）：
   - 个人：姓名、身份证号码、手机号
   - 企业：企业名称、统一社会信用代码、法人信息
6. 完成支付（支持微信/支付宝）

> ⏱️ **时间**：购买成功后域名即时生效（需实名认证后才能使用）

### 4.3 域名实名认证

域名购买后必须完成实名认证，否则无法使用。

1. 登录 [腾讯云控制台](https://console.cloud.tencent.com/cns) → **域名注册** → 找到你的域名
2. 点击 **「实名认证」**
3. 上传身份证照片 / 营业执照
4. 等待审核（通常 **1-3 个工作日**）

> ✅ **提示**：实名认证 ≠ 备案！这是两件不同的事：
> - **实名认证**：证明你是域名的所有者（1-3 天）
> - **ICP 备案**：证明你的网站内容合规（1-2 周）

### 4.4 ICP 备案（免费，但必须做！）

> **ICP 备案 = Internet Content Provider 备案**，是中国大陆监管要求。
>
> 所有使用中国大陆服务器/CDN 的网站**都必须备案**，否则会被拦截。

#### 备案前置条件

| 条件 | 要求 | 你的情况 |
| ---- | ---- | -------- |
| 域名 | 已购买并通过实名认证 | 步骤 4.2-4.3 完成 ✅ |
| 服务器 | 腾讯云国内 CVM 或轻量服务器 | 你已有 CVM 服务器 ✅ |
| 域名 | 非 `.top` 等限制性后缀（`.com`/`.cn` 均可） | - |

#### 备案流程（约 1-2 周）

```
① 登录腾讯云备案系统
   ↓ （10 分钟）
② 填写主体信息（个人/企业基本信息）
   ↓ （10 分钟）
③ 填写网站信息（域名、网站名称、用途）
   ↓ （1 个工作日）
④ 腾讯云初审（人工审核资料完整性）
   ↓ （通过后）
⑤ 手机扫码做人脸识别
   ↓ （提交管局）
⑥ 管局审核（各省通信管理局，约 5-15 个工作日）
   ↓ （通过后）
⑦ 收到备案号 → 备案完成！🎉
```

#### 详细操作步骤

**第一步：进入备案系统**

1. 登录 [腾讯云 ICP 备案控制台](https://console.cloud.tencent.com/beian)
2. 点击 **「开始备案」**
3. 选择你购买的域名

**第二步：填写主体信息**

| 项目 | 个人备案 | 企业备案 |
| ---- | -------- | -------- |
| 证件类型 | 身份证 | 营业执照 |
| 证件号码 | 身份证号 | 统一社会信用代码 |
| 联系方式 | 手机号 + 邮箱 | 手机号 + 邮箱 |
| 应急手机号 | 另一个手机号 | 另一个手机号 |

**第三步：填写网站信息**

| 项目 | 建议填写 |
| ---- | -------- |
| 网站名称 | 农场管理系统 / XX农场管理系统（不能含"中国"、"中华"等词汇） |
| 网站域名 | 你购买的域名（如 `farm-optimize.cn`） |
| 网站首页 URL | `www.farm-optimize.cn`（或你的实际域名） |
| 网站服务类型 | 信息服务平台 / 其他 |
| 网站内容 | 农场生产管理、餐厅经营管理系统 |
| 前置审批 | 无（一般网站不需要） |

> ⚠️ **注意**：网站名称不能包含以下词汇："中国"、"中华"、"人民"、"国家"等，也不能纯数字或英文。

**第四步：获取备案授权码**

备案需要你服务器的 **备案授权码**：

1. 腾讯云控制台 → **CVM 实例列表** → 选择你的服务器
2. 点击 **「更多」→「获取备案授权码」**
3. 复制授权码填入备案系统

**第五步：等待审核**

| 阶段 | 审核方 | 时长 | 注意事项 |
| ---- | ------ | ---- | -------- |
| 腾讯云初审 | 腾讯云 | 1 工作日 | 检查资料是否完整，有问题会电话联系 |
| 人脸识别 | 微信小程序 | 即时 | 用备案时填写的手机扫码 |
| 管局审核 | 省通信管理局 | 5-15 工作日 | 保持手机畅通，可能接到核实电话 |

**第六步：备案成功**

- 收到短信通知备案号（如：`粤ICP备XXXXXXXX号`）
- 在腾讯云控制台可查看备案状态
- 备案成功后即可绑定到 EdgeOne Pages！

#### 备案常见问题

| 问题 | 解决方法 |
| ---- | -------- |
| 备案被驳回 | 根据驳回原因修改（常见：网站名称不规范、证件不清晰） |
| 审核太久没结果 | 打 Tel 010-95716 腾讯云客服咨询 |
| 备案期间网站能用吗 | 备案期间不能访问国内节点，但可以先用海外区测试 |
| 个人还是企业备案？ | 个人备案更简单；企业备案可信度更高 |

### 4.5 时间规划建议

```
第 1 天：    购买域名 + 提交实名认证 ← 同时可做步骤②③（部署后端+本地验证）
第 1-3 天：  等待实名认证通过 ← 同时可做步骤②③
第 3 天：    提交 ICP 备案申请
第 3-20天： 等待备案审核 ← 这期间可以用 EdgeOne 默认域名（3小时预览链接）或选海外区测试
第 ~15天：   备案通过！← 立刻执行步骤⑤（绑定域名）+ 步骤⑥（全链路验证）
```

> 💡 **核心思路**：备案的等待时间不要浪费，**并行推进其他步骤**！

### 4.6 备案审核期间的临时部署方案 ⭐ 重要！

> **场景**：域名已购买但 ICP 备案还在审核中（通常 1-2 周），需要先上线测试。
>
> **核心思路**：利用 **EdgeOne Pages 默认域名**（无需备案）+ **Edge Functions API 代理** 绕过域名限制。

#### 架构对比

| 阶段 | 前端访问方式 | API 通信方式 | 是否需要备案 |
| ---- | ------------ | ------------ | ------------ |
| **正式部署** | `https://你的域名` | 直连 `http://服务器地址:39080/api` | ✅ 需要 |
| **备案期间（本方案）** | `https://xxx.edgeone.cool` (EdgeOne 默认域名) | EdgeOne Edge Functions 代理 → 后端 IP | ❌ 不需要 |

#### 备案期间架构图

```
用户浏览器 (HTTPS)
    │
    ├── 页面请求 → EdgeOne Pages 默认域名 ← 无需备案！
    │              https://xxx.edgeone.cool
    │              ├─ Vue SPA 页面
    │              └─ 静态资源 (JS/CSS/图片)
    │
    └── API 请求 (/api/*)
         ↓
    EdgeOne Edge Functions (API 代理)  ← 关键组件！
         ↓ 转发到真实后端 IP
    http://服务器地址:39080/api/*   ← 绕过域名
```

#### 操作步骤（共 4 步）

##### 步骤 1：修改 `.env.production` 为相对路径

```env

# 备案通过后改回正式地址
# VUE_APP_API_BASE_URL=http://服务器地址:39080/api
# 或绑定自定义域名后
# VUE_APP_API_BASE_URL=https://你的域名/api
```

> ⚠️ **重要**：使用 `/api` 相对路径，让 API 请求走同源（由 Edge Functions 代理），避免跨域问题。

##### 步骤 2：配置 Edge Functions API 代理

在项目 `frontend/edge-functions/api/[[default]].js` 中确认以下配置：

```javascript
const BACKEND_URL = process.env.BACKEND_URL || 'http://服务器地址:39080';

export async function onRequest(context) {
  const { request } = context;
  const url = new URL(request.url);
  const path = url.pathname;       // 如 /api/login
  const search = url.search;       // 如 ?key=value
  const targetUrl = `${BACKEND_URL}${path}${search}`;

  try {
    // 转发请求到后端服务器
    const response = await fetch(targetUrl, {
      method: request.method,
      headers: request.headers,
      body: request.body,
      redirect: 'follow',
    });

    const responseData = await response.text();

    return new Response(responseData, {
      status: response.status,
      statusText: response.statusText,
      headers: {
        'Content-Type': response.headers.get('Content-Type') || 'application/json',
        'Access-Control-Allow-Origin': '*',
        'Access-Control-Allow-Methods': 'GET, POST, PUT, DELETE, OPTIONS',
        'Access-Control-Allow-Headers': 'Content-Type, Authorization, token',
      },
    });
  } catch (error) {
    return new Response(JSON.stringify({
      error: 'Backend connection failed',
      message: error.message,
      target: targetUrl,
    }), {
      status: 502,
      headers: { 'Content-Type': 'application/json' },
    });
  }
}
```

> 📌 **说明**：此函数会将所有 `/api/*` 请求转发到你的后端服务器 IP，并自动处理 CORS 跨域头。

## 九、常见问题排查

### 问题 1：前端页面正常，但 API 请求报 CORS 错误

**现象**：浏览器控制台显示 `Access-Control-Allow-Origin` 相关错误。

**解决**：

```bash
# 1. 确认后端 CORS Filter 生效
curl -H "Origin: https://example.com" \
     -X OPTIONS \
     http://服务器地址:39080/api/login -v
# 应该看到响应头中有 Access-Control-Allow-Origin

# 2. 如果没有，检查 WebConfig.java 中的 corsFilter Bean 是否正确
# 3. 确认后端已重新构建部署
```

### 问题 2：API 请求连接超时

**原因**：安全组未放行 39080 端口，或后端容器未启动。

**解决**：

```bash
# 1. 检查安全组是否放行 39080（应在 39000-40000 范围内）
# 2. 检查后端容器状态
docker compose ps

# 3. 从外部测试
curl http://服务器地址:39080/api/login
```

### 问题 3：本地前端验证时 API 请求 404

**原因**：vue.config.js 代理配置有误，或后端未启动。

**解决**：

1. 确认 `vue.config.js` 中 `target` 为 `http://服务器地址:39080/`
2. 确认后端容器正常运行：`docker compose ps`
3. 直接在浏览器访问 `http://服务器地址:39080/api/login` 确认后端可访问
4. 检查浏览器 F12 Network 面板，确认请求是否被代理转发

### 问题 4：登录成功但刷新后丢失登录状态

**原因**：Token 存储在 sessionStorage 中，刷新页面不会丢失。如果丢失，检查是否有其他问题。

**解决**：检查浏览器控制台是否有错误，确认 token 是否正确存储在 sessionStorage 中。

### 问题 5：Vue Router 刷新 404

**原因**：EdgeOne Pages 未配置 SPA Fallback。

**解决**：在项目根目录创建 `edgeone.json`（见步骤 5.5），重新部署。

### 问题 6：前端更新后用户看到的还是旧版本

**原因**：EdgeOne CDN 缓存了旧文件。

**解决**：

1. EdgeOne 控制台 → **缓存** → **刷新缓存** → 选择全站刷新
2. 或强制刷新：`Ctrl + Shift + R`
3. 长期方案：构建时给 JS/CSS 文件名加 hash（Vue CLI 默认已做）

### 问题 7：Docker 构建超时/OOM

```bash
# 查看服务器内存
free -h

# 如果内存 < 2GB，建议本地打包再上传 jar
cd backend
mvn clean package -DskipTests
# 然后上传 jar 并使用简化版 Dockerfile
```

**简化版 Dockerfile（跳过 Maven 编译）**：

```dockerfile

> 使用此 Dockerfile 时，先在本地 `mvn clean package -DskipTests`，然后上传 `backend/` 整个目录（含 `target/`）。

### 问题 8：API 请求返回 Mixed Content 错误

**现象**：前端是 HTTPS（EdgeOne），但 API 请求是 HTTP，浏览器阻止混合内容。

**常见原因**：`index.html` 中引用了 HTTP 协议的外部资源（如阿里图标库 CDN）。

**解决**：

1. **排查方法**：浏览器 F12 控制台搜索 `Mixed Content`
2. **修复方法**：将所有 `http://` 外部资源改为 `https://`

```html
<!-- frontend/public/index.html -->

<!-- ❌ 错误 -->
<link rel="stylesheet" href="http://at.alicdn.com/t/font_xxx.css" />

<!-- ✅ 正确 -->
<link rel="stylesheet" href="https://at.alicdn.com/t/font_xxx.css" />
```

> 📌 **完整修复指南**：见 [4.6 备案审核期间的临时部署方案 → 步骤 3](#步骤-3修复-mixed--content问题必须)

### 问题 9：API 请求返回 405 Method Not Allowed

**现象**：登录或 API 调用时，控制台报错 `405 (Method Not Allowed)`。

**原因**：使用 EdgeOne Pages + `/api` 相对路径时，**未配置 Edge Functions API 代理**。EdgeOne Pages 默认只处理静态文件，不代理 API 请求。

**解决**：

1. 确认 `.env.production` 使用的是 `/api` 相对路径
2. 在 EdgeOne Pages 控制台 → **边缘函数** 菜单创建新函数
3. 匹配路由设为 `/api/*`
4. 粘贴 [Edge Functions 代理代码](#步骤-2配置-edge-functions-api-代理)

### 问题 10：上传 zip 到 EdgeOne 控制台报"文件名包含非法字符"

**现象**：在 EdgeOne Pages 控制台上传 zip 文件时报错 `文件名称包含非法字符（\ / : * ? " < > | ）`。

**原因**：PowerShell 的 `Compress-Archive` 打包的 zip 编码格式可能不被 EdgeOne 接受。

**解决**：使用 Node.js 的 `archiver` 库打包（兼容性更好）：

```bash
cd frontend

# 安装打包工具（仅需一次）
npm install --save-dev archiver --registry=https://registry.npmmirror.com

# 创建 create-zip.js 并执行
node create-zip.js
```

**create-zip.js 内容**：

```javascript
const archiver = require('archiver');
const fs = require('fs');
const path = require('path');

const output = fs.createWriteStream(path.join(__dirname, 'dist-deploy.zip'));
const archive = archiver('zip', { zlib: { level: 9 } });

output.on('close', () => console.log(`✅ ZIP created: ${(archive.pointer() / 1024 / 1024).toFixed(2)} MB`));
archive.on('error', (err) => { throw err; });
archive.pipe(output);
archive.directory(path.join(__dirname, 'dist'), false);
archive.finalize();
```

### 问题 11：MCP 部署工具每次都创建新项目

**现象**：使用 MCP 工具多次部署后，发现创建了多个项目而不是更新同一个。

**原因**：EdgeOne Pages MCP 工具当前版本**不支持指定已有 Project ID**，每次调用都会自动创建新项目。

## 十一、进阶：为后端 API 配置 HTTPS（可选）

> 当前方案中，前端 EdgeOne 是 HTTPS，但后端 API 是 HTTP。
> 部分浏览器可能阻止 HTTPS 页面请求 HTTP 资源（Mixed Content）。
> 如果遇到此问题，可按以下步骤为后端配置 HTTPS。

### 方案：在 CVM 上用 Nginx 做 HTTPS 代理

1. 用宝塔面板申请 Let's Encrypt 免费 SSL 证书
2. 在服务器上安装 Nginx（宝塔自带）
3. 配置 Nginx 反向代理：

```nginx
server {
    listen 443 ssl;
    server_name api.你的域名;

    ssl_certificate     /www/server/ssl/api.你的域名.pem;
    ssl_certificate_key /www/server/ssl/api.你的域名.key;

    location / {
        proxy_pass http://127.0.0.1:39080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

4. 修改 `.env.production`：
```
VUE_APP_API_BASE_URL=https://api.你的域名/api
```

5. 重新构建前端并部署到 EdgeOne
